## 3. 已拿到的硬证据（客户端真实 wire，2026-10-24 实测）

**这批证据推翻了旧文档的两处结论**（旧《风控校验-5.8.4》§7 第 4 行说 refresh 头一致——实测不一致；`风控差异清单` §二第 4 条关于 refresh/billing 的推断也要按下面修正）。

客户端**每个接口由不同内部组件发出**，头族/大小写/UA 各不相同：

| 接口 | 客户端实测头 | 对 hub 的含义 |
|---|---|---|
| `POST /v2/plugin/auth/token/refresh` | 仅 11 个头，**无** Origin/Referer/X-Requested-With/X-CodeBuddy-Request/Accept-Language；UA 双段 `workbuddy-ai/5.8.4 workbuddy-ai/5.8.4 CLI/2.161.0`；X-Request-ID 为 32hex；`X-Auth-Refresh-Source: plugin` | hub 的 refresh 多发 5 个浏览器头、UA 是单段 `WorkBuddy/5.8.4`（`cfg["billing_ua"]`），**形态不符** |
| `GET /v3/config` | 带 `X-Requested-With: XMLHttpRequest`，无 Origin/Referer，`Connection: close`，无 Accept-Encoding，双段 UA | hub 的目录抓取头集合不同 |

## 5. 本轮踩坑记录（别再踩）

1. `taskkill /PID` 在 Git Bash 里会被转成路径——用 PowerShell `Stop-Process`；
2. 杀提权进程必须把 Stop-Process 放进 `Start-Process -Verb RunAs` 的**内层**脚本；
3. 往 PEM bundle 追加证书前必须保证原文件以换行结尾（本轮坏过一次，Node 报 `bad end line`）；已用 python 重建修复；
4. 便携 hub 是 Windows Python，`ssl.create_default_context()` **不读系统证书库**；要让 hub 被 MITM 需 `WB_CA_BUNDLE=<含 mitm CA 的 pem>` 重启（且**不能加 `--lan`**，会强制 API key）；用户不要求抓 hub，别再动它；
5. 内置 CLI（`cli/bin/codebuddy -p`）手动跑不通：它按 `authentication.id` 配置找凭证（`%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\<id>.info`），桌面端会注入该配置而手动没有——除非解决注入，否则别再试；
6. 客户端 spawn CLI 的环境变量（复刻用）：`CLIENT_INFO_PLATFORM/PLATFORM_VERSION/IDE_TYPE=WorkBuddy、PRODUCT_NAME=workbuddy-ai、PRODUCT_VERSION=5.8.4、PLUGIN_NAME/VERSION` + `NODE_EXTRA_CA_CERTS=~/.workbuddy-ai/system-ca-bundle.pem`，node 在 `~/.workbuddy-ai/binaries/node/versions/22.22.2-6/node.exe`。
